## 플레이어 약속

- 한 문장 약속: 실제 랭킹 사용자의 기록을 가진 총잡이와 마주 서서, `DRAW!`가 뜨는 순간 단 한 번 눌러 반응속도를 겨룬다.
- 톤 전제: 텍사스의 낡은 술집 앞에서 플레이어 전신 원본의 오른쪽 얼굴·오른팔·허리 홀스터와 리볼버만 화면 왼쪽 아래에 걸치고, 나머지 몸과 다리는 뷰포트 밖에 둔다. 상대는 중앙에서 한 발을 쏘며 느린 쪽만 쓰러진다.
- 핵심 실력: 예측하지 않고 신호를 기다리는 집중력과 첫 시각 신호에 대한 순수 반응속도
- 세션 모델: 단발 clear-time형 반응속도 점수전
- 예상 플레이 시간: 약 9~15초(가설, 결과 연출 포함)
- 절대 최대: 30초. 5분을 넘지 않는다.

## 20초 가이드 계약

> `DRAW!`가 나타나면 화면을 한 번 누르세요. 먼저 누르면 총을 쏘지 않고 `너무 빨리 눌렀어요`를 보여 주며 무기록 패배합니다. 상대의 실제 기록과 결투하지만, 승패와 관계없이 내 반응속도로 순위가 정해집니다. 상대가 없으면 봇이 등장합니다.

- 목표: 신호 후 가능한 한 빨리 한 번 발사한다.
- 조작: 화면의 넓은 발사 영역에 새 pointer-down 한 번
- 점수: 신호가 보인 시점부터 첫 유효 입력까지의 시간을 `0.123초`처럼 표시하며 낮을수록 좋다.
- 주요 실패: 신호 전 조기 발사, 신호 후 1,000ms 동안 미입력, 반응 확정 전 앱 이탈
- 예상 읽기 시간: 약 12~15초

## 핵심 루프

- 초기 상태: 서버가 상대 기록을 고정하고 에셋을 준비한 뒤 3.2초 안전 카운트다운을 보여 준다.
- 대치: 카운트다운 뒤 3~8초 동안 화면 왼쪽 아래에 플레이어 전신 원본의 오른쪽 가장자리만 보이며, 오른손은 허리 홀스터 근처에 준비하고 중앙의 상대 전신은 움직임을 억제한다. 바닥 중앙에는 낮은 대비의 모래바람 한 줄과 마른 낙엽 하나가 장식 전용 난수로 매 대치마다 출현 간격·속도·높이·잔물결 위상을 달리하며 천천히 지나가고, 발사와 결과 연출 중에도 사라지지 않는다. 플레이어는 온전한 전신 atlas를 뷰포트 밖에 배치하므로 허리 아래는 화면에 그리지 않을 뿐 에셋에서 삭제하지 않는다. 이 구간의 새 pointer-down은 발사 없이 즉시 조기 입력 패배다.
- 신호: 예고 동작·소리·먼지·빛 없이 `DRAW!`를 처음 그리는 논리 시점과 단조 증가 시계의 측정 시작점을 일치시킨다.
- 입력: 신호 뒤 첫 새 pointer-down을 1,000ms deadline까지 측정한다. deadline에 도달하면 입력 없이 `1.000초` 기록으로 종료한다.
- 판정: 내 반응시간과 시작 시 고정된 상대 반응시간을 비교한다. 승패는 제출 점수를 바꾸지 않는다.
- 결투 연출: 유효 입력 결과에서는 상대와 플레이어가 각각 한 발씩 발사한다. 상대가 먼저 발사한 경우에도 플레이어가 발사할 때까지 명중·입력 차단을 하지 않는다. 두 총구 섬광은 각자 정확히 한 번만 보인다. 두 발사가 끝난 뒤 빠른 쪽 탄환만 명중하고 느린 쪽은 전방 낙하한다. 승자는 총을 입가에 올린 뒤 총구의 연기를 불어낸다. 조기 입력이나 1초 무입력은 플레이어의 가짜 총성을 만들지 않는다.
- 동률 연출: 양쪽 모두 한 발씩 발사하지만 두 탄환 모두 아슬아슬하게 빗나가고 둘 다 서 있는 무승부로 끝난다.
- 완료: `나 0.284초 / 상대 0.231초`처럼 양쪽 기록과 승패를 함께 보여 주고 내 유효 기록만 제출한다.
- 실패: 조기 발사는 기록 없이 종료하고, 1초 무입력은 `1.000초`를 제출하는 게임오버로 종료한다.
- 카메라: 측정과 결과 연출 모두 술집 정면을 바라보는 고정 세로 2D 1인칭 화면이다. 월드 스크롤·줌·회전은 사용하지 않으며, 느린 플레이어의 전방 낙하가 패배 연출을 담당한다.

## 입력 계약

- 제스처: pointer-down 한 번만 판정한다. pointer-up, 드래그, hover는 사용하지 않는다.
- 유효 영역: HUD 안전영역을 제외한 넓은 하단 발사 영역. 실제 경계는 가이드와 런타임에서 동일해야 한다.
- 카운트다운: 첫 3.2초의 입력은 무시하며 실패를 만들지 않는다.
- 대치 중 입력: 새 pointer-down 즉시 조기 입력 패배로 확정하고 이후 입력을 받지 않는다. 플레이어 발사 상태·총구 섬광은 시작하지 않는다.
- 신호 후 입력: 첫 새 pointer-down만 유효하다. 대치 전부터 누르고 있던 손가락은 발사로 승격하지 않는다.
- 상대 선발사: 상대 기록 시점에 상대 총구 섬광을 정확히 한 번 재생할 수 있지만, 그 시점에는 플레이어를 맞히거나 화면을 기울이거나 입력을 막지 않는다. 플레이어의 첫 새 pointer-down이 들어올 때 플레이어 총구 섬광도 정확히 한 번 재생하고, 두 발사 이벤트가 모두 끝난 뒤에만 승패 명중·빗나감·쓰러짐을 연출한다.
- 멀티터치: 같은 입력 배치의 첫 pointer-down 하나만 판정하고 나머지는 무시한다. 여러 손가락을 미리 대고 있는 행위는 이점을 주지 않는다.
- 피드백: 유효 입력은 즉시 짧은 햅틱을 주되 화면은 두 기록 비교와 양쪽 섬광이 끝날 때까지 고정한다. 조기 입력은 플레이어 총성 없이 `너무 빨리 눌렀어요`로 원인을 보여 준다.

## 상태 머신

```text
loading
  ├─ 상대/에셋 준비 성공 → countdown_safe
  └─ 준비 실패 → interrupted(no score)
countdown_safe(3.2s)
  → standoff(3~8s)
      ├─ pointer-down → false_start(no score)
      └─ wait complete → draw_active
draw_active
  ├─ 상대 기록 시각 도달 → opponent_fire_flash_once(입력 계속 허용)
  ├─ first pointer-down < 1,000ms → compare
  ├─ 1,000ms expiry → timeout(1.000초 기록, player_forward_fall)
  └─ app background/engine stop → interrupted(no score)
compare
  → both_fire_resolution(win/lose/draw; 양쪽 섬광 각 1회 보장, 느린 플레이어는 전방 낙하)
  → finished(valid score, exactly once)
```

- `compare`에 진입한 뒤에는 반응시간이 확정되었으므로 결과 연출 중 앱이 내려가도 확정 기록을 보존하고 정확히 한 번 제출한다.
- 상대 기록이 플레이어보다 빠르면 `opponent_fire_flash_once`가 먼저 재생되지만 플레이어의 입력을 기다리는 동안 명중·피격·입력 차단을 하지 않는다. 플레이어 입력 시 플레이어 섬광을 한 번만 재생하고, 두 발사의 시각 이벤트가 모두 소비된 뒤 `both_fire_resolution`이 승패 결과를 적용한다.
- 플레이어 기록이 상대보다 빠르면 플레이어 섬광 후 상대 섬광을 한 번 재생한 뒤 같은 해상도 규칙으로 결과를 적용한다. 동률은 두 섬광을 재생하고 두 탄환을 모두 빗나가게 한다.
- `false_start`, `interrupted`는 공식 시도를 소모하지만 랭킹 점수를 만들지 않는다. `timeout`은 `reaction_ms=1000`, `raw_score=999000`을 제출하고 게임오버 처리한다.

## 콘텐츠 확장성과 Codex 적합성

- 수작업 맵: 1개의 고정 결투 거리 배경
- 수작업 스테이지: 없음
- 재사용 패턴: 대기, 양쪽 발사, 승리, 패배, 동률의 5개 연출
- 버전 1 에셋 계열: 정면 상대 전신 1계열 + 플레이어 전신 원본을 좌하단에 배치한 통합 전경 1계열, 배경 1계열, FX 2~3계열, UI 1계열
- 변화 원천: 실제 상대 닉네임·닉네임 색상, 상대 반응 기록, 대치 시간, 승패
- 수치 제어: 대치 시간, 반응 창, 봇 기록 범위, 애니메이션 길이
- 지속적으로 맵이나 적 패턴을 추가하지 않아도 실제 사람 기록이 매 결투의 상대성과 긴장을 만든다.
- 구현 복잡도: 클라이언트 상태 머신은 작지만 서버의 원자적 상대 배정과 이력 분리가 핵심이다.
- 자동화 테스트: 순수 규칙 모듈로 시간 비교·점수 변환·동률·실패를 검증하고, 서버 SQL 테스트로 공정 배정과 멱등성을 검증한다.

## 무작위성과 한 번뿐인 시도의 공정성

- 무작위 소스: 서버가 실제 플레이 시작 시 확정한 시도별 비예측 seed
- 무작위 요소: 3~8초 대치 시간, 동일 우선순위 후보 중 상대 선택, 봇 반응시간
- 같은 날짜의 공용 game seed만 사용하지 않는다. 추가 도전으로 신호 시점을 외울 수 없어야 한다.
- 신호 이전에는 `DRAW!` 출현을 예고하는 애니메이션·오디오·햅틱·FX를 만들지 않는다.
- 상대 선정은 같은 날짜·같은 `western_duel` 규칙 버전의 유효 랭킹에서 사용자별 현재 최고 기록 하나를 후보로 한다.
- 본인, 테스트 계정, 실격·중단 기록은 후보에서 제외한다.
- 당일 전역 상대 배정 횟수가 가장 적은 사용자 집합을 우선하고 그 안에서 균등 무작위 선택한다. 따라서 아직 한 번도 선택되지 않은 사용자가 먼저 소진된다.
- 실제 플레이 시작 확인과 함께 서버가 상대 score ID, 사용자 ID, 닉네임, 닉네임 색상, 반응 ms를 원자적으로 스냅샷한다.
- 같은 시도에서 배정 RPC를 재호출하면 같은 상대를 반환한다. 이후 상대의 최고 기록이 바뀌어도 진행 중 스냅샷은 바뀌지 않는다.
- 후보가 없으면 새로 배정되는 봇을 `맥크리`로 표시한다. 기존 저장된 상대 이름은 유지한다. 봇은 랭킹과 인간 상대 배정 횟수에 포함하지 않는다.
- 서버 통신 실패는 후보 없음으로 위장하지 않고 시도를 시작하지 않는다.
- 연습 플레이는 인간 상대의 전역 배정 횟수를 소모하지 않는다.
- 입력 spam은 첫 pointer-down만 판정하며, 앱 일시정지·시스템 UI·백그라운드 전환으로 시간을 멈춘 뒤 재개할 수 없다.

## 점수와 랭킹

- 플레이어 표시값: 반응시간 초 단위 소수점 세 자리, 예: `0.123초`
- HUD: 측정 전에는 점수를 숨기고 결과에서 나와 상대 기록을 함께 표시한다.
- 제출 기준: 승패가 아닌 내 유효 반응시간만 사용한다.
- 정밀도: 내부 반응시간은 정수 ms. 실시간 입력 deadline은 1,000ms이며 저장·상대 호환 검증 범위는 1~1,500ms이다.
- 내림차순 랭킹 인코딩: `raw_score = 1,000,000 - reaction_ms`
- 역변환: `reaction_ms = 1,000,000 - raw_score`
- 포맷: `reaction_ms / 1000`을 항상 소수점 세 자리로 표시한다.
- 동률: 같은 ms는 결투상 무승부다. 랭킹의 같은 표시값 정렬은 공통 랭킹의 기존 안정 정렬 규칙을 따른다.
- 상대 승패, 상대 수준, 인간/봇 여부는 제출 점수에 영향을 주지 않는다.
- 오발과 반응 확정 전 중단은 점수를 제출하지 않는다. 무입력 timeout은 `1.000초`를 제출한다.
- 반응 확정 뒤 결과 연출 중 중단은 이미 확정된 점수를 정확히 한 번 제출한다.
- 서버는 attempt 소유권, 게임 ID·버전, 점수 범위, 최소 진행시간, 중복 제출을 검증한다. 클라이언트가 실제 인간 입력을 측정했는지 완전히 증명할 수 없다는 한계는 남는다.

## 프레젠테이션 의존성

### 2D 비주얼 콘셉트

- 배경: 플레이어 시점에서 정면으로 보이는 텍사스풍 낡은 목조 술집, 중앙 문과 간판, 황토색 거리, 말 매는 기둥과 낮은 물통
- 화면: 360×720 논리 픽셀의 세로 고정 2D 1인칭 화면. 플레이어 전신 원본을 좌하단 화면 밖으로 밀어 오른쪽 얼굴 일부·오른팔·리볼버·허리 홀스터만 보이고, 정면 상대는 화면 중앙에 둔다.
- 분위기: 뜨겁고 조용한 정오, 황토·적갈색·탁한 청록 중심. `DRAW!`와 총구 섬광만 가장 밝다.
- 연출 장치: 양쪽 모두 한 발을 쏘지만 느린 쪽의 탄환은 술집 간판이나 물통을 맞히고, 두 발사가 끝난 뒤 느린 쪽만 쓰러진다. 상대 선발사 중에는 플레이어가 발사할 때까지 피격 연출을 유예한다.
- 픽셀 방향: 전경의 겉보기 픽셀은 약 2×2 논리 픽셀. 배경은 캐릭터와 신호보다 낮은 대비와 세부 밀도를 유지한다.
- 압박 변화: 안전 카운트다운에는 정보가 안정적이고, 대치 중 배경 움직임은 최소화하며, 신호 순간만 화면 중심 대비가 급격히 상승한다.

### 총잡이

- 역할: 기록 상대는 플레이어를 정면으로 바라보는 성인 총잡이 전신이다. 플레이어는 온전한 전신 원본을 왼쪽 아래에 배치하고, 화면에는 모자·얼굴 오른쪽·오른팔·리볼버·허리 홀스터의 필요한 가장자리만 노출한다. 바지와 다리는 뷰포트 밖에 남으며 화면 속 물리적인 오른손으로 홀스터에서 총을 뽑는다.
- 실루엣: 성인 비율의 낡은 카우보이모자, 가죽 조끼, 셔츠, 부츠, 홀스터. 모자와 어깨선은 작은 화면에서도 읽혀야 한다.
- 표정: 과장된 만화 표정 없이 긴장된 눈썹과 굳은 입을 사용한다.
- 움직임: 대치 중에는 호흡과 옷자락만 최소한으로 움직이며, 조준·발사·반동·피격·쓰러짐을 명확한 큰 포즈로 구분한다.
- 정체성 단서: 닉네임 색상을 모자띠나 스카프에 제한적으로 반영한다.
- 필수 동작: 상대 대기, 상대 발사, 상대 명중·쓰러짐, 상대 빗나감·잔류. 플레이어의 온전한 전신·오른팔·손·리볼버·홀스터가 하나의 4×4 v11 atlas에서 준비, 손잡이 잡기, 뽑기, 조준, 발사, 반동, 정착까지 함께 움직인다. 화면 밖에 배치해 필요한 전경만 노출하며 에셋 자체에서 바지·다리·장화를 삭제하지 않는다.
- 결과: 상대와 플레이어의 총구 섬광은 각각 정확히 한 번만 보인다. 빠른 탄환의 명중과 느린 탄환의 배경 탄착을 분리해 보여 준다.

### 시각적 역할과 UI

- 목표: 상대 쪽의 `DRAW!`와 하단 발사 영역
- 위험: 대치 중 조기 입력. 별도 가짜 신호는 두지 않는다.
- 이름표: 상대 닉네임을 캐릭터 위에 표시한다. 새 봇의 닉네임은 `맥크리`이며, `BOT ·` 접두사는 표시하지 않는다.
- 성공/실패: 승자는 총구 연기 속 긴장 완화 포즈, 패자는 두 발사가 끝난 뒤 피격 충격과 함께 시점이 짧게 기울어진다. 상대 선발사 순간에는 이 결과 연출을 시작하지 않는다.
- 빗나감: 느린 쪽 탄착은 캐릭터와 겹치지 않는 배경 소품에서 먼지·파편으로 보인다.
- 가이드: 대치, `DRAW!`, 양쪽 발사 결과의 3페이지를 권장한다. 가이드 장면은 설명용 연출이며 실제 무작위 타이밍으로 오해되지 않게 한다.
- 홈 미리보기: 술집 정면, 중앙 상대와 닉네임, 화면 왼쪽 아래 플레이어의 얼굴 오른쪽·오른팔·홀스터·리볼버가 한 화면에 보여야 한다.

#### 1인칭 구도 계약

- 기준 뷰포트는 360×720이다. 배경은 술집 정면의 중앙 문과 간판이 화면 중심선에 놓이도록 정렬한다.
- 상대 전신의 중심 x는 180px, 발 기준 y는 430px이다. 상대 머리·손·부츠가 모두 화면 안에 남고 이름표·`DRAW!`가 얼굴을 가리지 않아야 한다.
- 플레이어 전경은 v11 idle/action 디테일 atlas를 좌하단에 배치하며, 540×1080 기준 origin은 `(-254,height−680)`, 표시 크기는 `540×1080`이다. v11은 기존 픽셀 정체성과 구도를 유지하면서 모자·얼굴·조끼·소매·손·리볼버의 내부 색면과 윤곽 디테일을 상대 에셋 수준으로 높인다. 화면에는 얼굴 오른쪽·오른팔·리볼버·홀스터의 필요한 부분만 남고, 몸통·다리는 뷰포트 클리핑으로 가려진다. 대기 4프레임 idle atlas는 동일한 master를 반복하고, 허리·홀스터를 고정한 세로 ±0.9% 호흡(머리 약 3px)만 3초 주기로 적용한다. action atlas는 16개의 고유 포즈 슬롯으로 구성한다. 1~7번 grip/draw/aim 프레임은 각 0.03초, 8번 shoot 프레임(0-based index 7)은 0.21초에 시작하며, 9~11번 recoil과 12~16번 settling 프레임은 각 0.04초로 총 0.57초 재생한다. 몸통 root는 고정하고 총구점은 소스 `(410,365)`에서 화면 `(156,height−315)`으로 계산한다. 발사 섬광은 이 총구에서 상대 직사각형 상단 기준 38% 지점으로 향하는 각도를 매 프레임 계산해 회전한다.
- 패배 낙하는 v13 2×4 atlas를 80ms 동안 실제 발사/대기 포즈와 crossfade한 뒤 무릎을 꿇고 0.38초간 자세를 유지하다가 앞으로 엎어진다. 팔은 바닥을 짚지 않고 뒤로 힘없이 늘어진다. 전체 전신은 하나의 레이어로 시작하며 낙하 렌더 사각형은 65% 배율로 줄고, 완료까지 `+45px,+40px`의 전방 이동을 적용한다. 별도 팔·몸통 분리나 카메라 회전은 사용하지 않는다.
- 레이어 순서는 `배경 → 상대 전신 → 이름표/신호 → 총알·섬광·명중 FX → 플레이어 전경 → 결과 HUD`다. 플레이어 전경은 입력 영역과 시각적으로 연결되지만 HUD를 덮지 않는다.
- 측정 중에는 모든 레이어의 카메라 좌표가 고정이다. 상대 선발사 섬광은 해당 시각에 그 레이어에서 한 번만 재생하고, 플레이어 입력 전에는 피격 FX를 예약만 한다.
- 360×640..800 논리 뷰포트에서 대기 중에는 얼굴 오른쪽·오른팔·홀스터가, 뽑기와 발사 중에는 오른팔·리볼버·총구가 식별 가능하게 남는다. 전신 atlas의 왼쪽과 하체는 좌하단 배치와 뷰포트 클리핑으로 화면 밖에 남으며, 에셋 내부의 인위적인 하체 절단선은 없어야 한다. 438×898 비율, iPhone 16 Plus 430×932, 사용자 첨부 640×976 크기를 실제 런타임 렌더러로 검수한다.

## 기술 적합성

- 런타임: Flame 고정 화면과 작은 명시적 상태 머신
- 순수 규칙: 대치 생성, 반응시간 검증, 승패 비교, 점수 인코딩·포맷을 UI와 분리한다.
- 서버: 신규 `western_duel` 게임/규칙, 상대 스냅샷과 당일 배정 횟수, 멱등 배정 RPC, 전용 점수 검증이 필요하다.
- 레지스트리: 향후 일일 편성은 `mole_reaction` 대신 `western_duel`을 사용한다. 과거 이력 포맷을 위해 기존 등록과 점수 해석은 보존한다.
- 앱 생명주기: 공통 pause→resume을 그대로 허용하지 않고, 반응 확정 전 일시정지·백그라운드는 중단 처리한다.
- 주요 위험: 렌더 신호와 입력 시계의 오차, 클라이언트 점수 위조, 동시 상대 배정 경쟁, 구버전 기록 혼합, 큰 dirty worktree와의 충돌

## 합격 테스트

- 가이드를 약 20초 안에 이해할 수 있다.
- 첫 실패 가능 입력은 시작 3.2초 이후에만 나타난다.
- 같은 시도에서 상대 배정을 재호출해도 같은 스냅샷을 반환한다.
- 인간 후보는 날짜·게임·버전·본인·테스트 계정 필터를 지킨다.
- 배정 0회 사용자가 1회 이상 사용자보다 우선하고, 동시 요청에서도 배정 횟수가 원자적으로 유지된다.
- 후보가 없을 때만 명시적 봇을 사용하며 서버 오류를 봇으로 위장하지 않는다.
- 신호 전 입력은 오발 무기록, 신호 후 999ms까지의 첫 새 입력만 유효하며, 1,000ms 미입력은 `1.000초` timeout 기록을 만든다.
- 패배한 `284ms`도 승패와 무관하게 `0.284초`로 제출·표시된다.
- 결과에서 양쪽 모두 한 발씩 발사하고, 빠른 쪽만 명중하며 느린 쪽 탄환은 빗나가고 느린 쪽만 쓰러진다.
- 상대가 먼저인 기록에서 플레이어가 늦게 입력해도 플레이어 섬광이 정확히 한 번 보인 뒤에만 결과 판정이 적용된다.
- 플레이어가 먼저인 기록에서도 플레이어 섬광과 상대 섬광이 각각 정확히 한 번 보이고, 두 섬광 뒤에만 승패 연출이 시작된다. 느린 플레이어는 자기 발사 시각 직후 전방 낙하를 시작한다.
- 1인칭 기준 뷰포트에서 중앙 상대 전신, 화면 왼쪽 아래 플레이어의 얼굴 오른쪽·오른팔·총, 술집 정면 배경, `DRAW!`, 이름표, 발사 영역이 서로 겹치지 않는다.
- 측정 중과 결과 연출 중 카메라의 위치·줌·회전 값은 고정이며, 느린 플레이어의 전방 낙하 atlas가 패배 연출이다.
- 동률이면 양쪽이 발사하지만 둘 다 빗나가고 무승부가 된다.
- `123ms ↔ raw_score 999,877 ↔ 0.123초`가 왕복 보존된다.
- 오발·미입력·반응 확정 전 중단은 점수를 만들지 않는다.
- 반응 확정 뒤 결과 연출 중 중단은 점수를 정확히 한 번 제출한다.
- 같은 날짜의 반복 시도에서도 대치 시간을 예측할 수 없다.
- 과거 `mole_reaction` 기록이 `western_duel` 랭킹이나 포맷에 섞이지 않는다.
- 360×640·360×720·360×800 기준 화면에서 상대 전신, 플레이어의 얼굴 오른쪽·오른팔·오른손·총구·홀스터, 신호, 이름표, 발사 영역의 필수 영역이 의도치 않게 잘리거나 겹치지 않는다. 전신의 하체 비노출은 뷰포트 클리핑으로만 발생한다.
- 모든 정상·실패 경로가 30초 안에 종료된다.
- 기존 `master_character` 마스터와 두더지 에셋은 원본으로 보존되고, 새 1인칭 원본은 별도 경로에서만 참조된다.

## 밸런스 가설

| 가설 | 필요한 증거 | 조정값 |
|---|---|---|
| 3~8초 대치가 긴장감을 만들고 피로하지 않다 | 20명 이상 반복 플레이 영상과 오발률 | 대치 최소·최대 |
| 1,000ms deadline이면 의도적 미입력을 결정적으로 처리할 수 있다 | 실기 반응 분포 | 응답 deadline |
| 350~550ms 봇이 초반 사용자에게 지나치게 강하거나 약하지 않다 | 봇 상대 승률 | 봇 범위·분포 |
| 결과 1~2초 안에 양쪽 발사와 명중/빗나감을 읽을 수 있다 | 360px 실기 캡처 | 애니메이션 타이밍 |
| 정수 ms 랭킹이 기기 차이에도 납득 가능하다 | iOS/Android 입력 지연 계측 | 표시 문구·동점 정책 |

## 미결정 사항

- 영문 표기는 현재 가제 `Western Duel`이다. 한국어 게임명은 `딱 한 발만`으로 확정했다.
- 총잡이 외형, 정확한 팔레트, 애니메이션 프레임과 사운드는 에셋 승인 단계에서 확정한다.
- 서버가 허용할 비현실적으로 빠른 기록의 하한과 추가 부정행위 탐지 정책은 구현 전에 실제 기기 계측으로 정한다.
